# Buyer deployment profiles

The image and runtime are portable to Google Cloud Run, Azure Container Apps, AWS ECS/Fargate, and Kubernetes (GKE, AKS, EKS). None of these paid resources are provisioned for the free test.

Use a separate Firebase project, credentials, buckets, signing keys, SSO registration and hostname per staging/production environment. Runtime validation in `ProductionConfiguration` rejects incomplete production settings. Supply `PORT`, `SPRING_PROFILES_ACTIVE=production`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET`, ADC credentials or workload identity, `RADIOTECH_FIREBASE_WEB_API_KEY`, independent report/invitation signing keys and exact HTTPS/CORS origins. Never bake credentials into the image. For the Kubernetes secret mount set `GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/firebase/credentials.json`.

Cloud Run: use instance-based CPU allocation and at least one minimum instance for the background plan/SLA/outbox worker; otherwise deploy a separate always-on worker or scheduled job. Container Apps: retain at least one replica for automation and use managed secrets and private ingress/egress rules. ECS/Fargate: run an always-on service behind an HTTPS application load balancer, use Secrets Manager and task IAM roles. Configure Google workload federation for Azure/AWS rather than long-lived service account keys when supported by the buyer's IAM.

Kubernetes: `kubernetes/deployment.yaml` provides rolling updates, probes, restricted container privileges and a disruption budget. Replace the image digest and external secret bindings; configure company ingress/TLS and egress network policy before applying. The placeholders deliberately cannot deploy a usable image. Enable a metrics scraper with `RADIOTECH_METRICS_TOKEN` (random secret of at least 32 characters) at `/actuator/prometheus`; keep metrics private. HTTP metrics, request correlation and the OpenTelemetry bridge are included; connect the buyer's telemetry collector and tracing sampling policy. Review outbound telemetry fields for personal data.

Release sequence: build once, run backend/emulator/web/mobile checks, sign and push the immutable image, deploy that digest to staging, perform customer/operator acceptance, then promote the same digest. Kubernetes commands: `kubectl set image deployment/radiotech api=<verified-image@sha256:digest>` and `kubectl rollout status deployment/radiotech`. Rollback: `kubectl rollout undo deployment/radiotech`, then verify readiness and role-isolation smoke tests. Cloud Run revisions and Container Apps revisions should likewise retain the previous immutable image. Rollback does not reverse data writes; preserve backward-compatible schemas.

SSO: enable Google for the free identity test if desired; Microsoft requires the buyer's Entra application registration. Authorize the actual web hostname in Firebase and Android signing certificate SHA256/SHA1 in the provider configuration. Set `RADIOTECH_SSO_ENABLED=true` for web and build mobile with `--dart-define=SSO_ENABLED=true` and the Google server client ID. SSO account creation grants no role: an administrator must associate the account. Managed TOTP MFA is implemented on web and mobile; enable Firebase Identity Platform and review its pricing before activation. Test email-password, SSO, MFA recovery and account revocation separately. Do not require MFA on an account before enrollment/recovery are confirmed.

Webhook activation: set `RADIOTECH_WEBHOOK_HOSTS` to a comma-separated list of trusted company-owned endpoint hosts and `RADIOTECH_WEBHOOK_SECRET` to an independent random secret (>=32 characters). Then enable the integration in the UI. The sender validates public IPs and pins the TCP connection to a validated address while verifying TLS against the hostname, with no redirects. Also restrict production egress to the approved endpoints on TCP443. Verify HMAC over `eventId.timestamp.rawBody` and enforce timestamp age plus event ID deduplication at the receiver. Delivery retries can repeat an event. Test invalid signatures, redirects, outages and exhausted retry attempts.

Backups: free test archives use AES256-GCM and a protected local key (`scripts/configure-free-backups.ps1`). Authenticated verification checks corruption; the recovery CLI permits writes only to demo emulators. Production needs an independent protected destination, retention, password-hash/MFA/provider configuration recovery, object streaming for large buckets, and a complete restore drill. Local snapshots are not a consistent point-in-time database export during concurrent writes; use maintenance mode for small test snapshots and managed backups/PITR for production.
